## final_verify.py —— 链接检查

**功能**：扫描笔记中的图片链接，报告哪些无法找到对应的文件。

**检查的链接类型**：
- `![](path/to/image.png)` — 标准 MD 图片链接
- `![image.png](image.png)` — Wiki 图片链接（仅统计数量，不检查有效性）

**输出信息**：
- 链接总数、正常数、损坏数
- 外部链接数（`http://` / `https://` 开头，不检查）
- 残留的 Wiki 链接数量
- 损坏链接的详细列表（最多展示 10 条）

**示例输出**：
```
File:     C:\Users\...\某笔记.md
  Total:    15
  Working:  12
  Broken:   2
  External: 1
  Wiki:     0

  Broken links:
    ![](attachments/old.png)
      -> not found: C:\...\attachments\old.png
```

## final_fix.py —— 链接修复

**功能**：自动修复笔记中损坏的图片链接。

**修复内容**：

| 操作 | 说明 |
|------|------|
| `![image.png](image.png)` → `![image.png](相对路径)` | Wiki 图片链接转为标准 MD 链接 |
| `![](中文 路径.png)` → `![](中文%20路径.png)` | 路径中的特殊字符做 URL 编码 |
| `![](错误路径)` → `![](正确路径)` | 根据文件名在 vault 中搜索，替换为正确相对路径 |

**支持的模式**：
- **单文件模式**（`single`）：修复一个指定文件
- **目录模式**（`dir`）：递归扫描整个目录，修复所有 `.md` 文件

**工作原理**：
1. 先扫描整个 vault（或单文件所在目录），建立"文件名 → 实际路径"的索引
2. 逐个处理 `.md` 文件：
   - 将所有 Wiki 图片链接转为 MD 格式
   - 检查每个 MD 图片链接，如果路径错误，通过文件名在索引中匹配
   - 对路径中的特殊字符做 URL 编码
3. 只有内容发生变化时，才回写文件

**示例输出**：
```
Building image index...
  Found 314 unique images

Processing .md files...

  [OK] 某笔记.md

============================================================
DONE!
  Files modified: 1
  Wiki->MD converted: 3
  Links re-encoded/fixed: 5
============================================================
```

## 配置说明

两个脚本均在文件顶部通过变量配置，无需命令行参数。

### final_verify.py

```python
MODE = "single"              # "single" = 单文件  |  "dir" = 扫描整个目录
TARGET_FILE = r"C:\...\某笔记.md"   # 单文件模式下的目标文件
VAULT_ROOT  = r"C:\...\Vault\测试"  # 目录模式下的扫描根目录
```

### final_fix.py

```python
MODE = "single"              # "single" = 单文件  |  "dir" = 扫描整个目录
TARGET_FILE = r"C:\...\某笔记.md"   # 单文件模式下的目标文件
VAULT_ROOT  = r"C:\...\Vault\test"  # 目录模式下的扫描根目录
```

### 切换模式

1. 修改 `MODE` 为 `"single"` 或 `"dir"`
2. 设置对应的 `TARGET_FILE` 或 `VAULT_ROOT`
3. 保存文件后直接运行 `python final_verify.py` 或 `python final_fix.py`

## 安全注意事项

### final_verify.py
- 完全只读，**不会修改任何文件**，可以放心运行 ✅

### final_fix.py —— 以下行为需注意

| 行为 | 影响范围 | 建议 |
|------|---------|------|
| Wiki 链接 `![[...]]` 会被转为 MD 链接 | **全部** Wiki 图片链接 | 如果 Wiki 链接本身能正常工作，建议提前备份 |
| 路径中的中文/空格会被 URL 编码 | **全部**含特殊字符的路径 | 编码后 Obsidian 也能正常解析，通常安全 |
| 根据文件名匹配图片位置 | 仅影响**损坏的** MD 链接 | 可能存在同文件名歧义 |

### 运行前建议

1. **先运行 `final_verify.py`** 了解当前状况
2. **Git commit 或手动备份** 目标目录
3. 先在少量文件上测试（单文件模式）
4. 确认无误后再使用目录模式批量处理

## 常见问题

### Q: 目录模式下，`final_fix.py` 会影响没问题的链接吗？

**会**，具体影响：

- ✅ **MD 链接且路径正确且编码一致** → 不会修改
- ⚠️ **MD 链接路径正确但编码不一致** → 会被重新编码（如中文被 URL 编码）
- ⚠️ **Wiki 图片链接（`![[...]]`）** → 会被转为 MD 链接，无论原来是否正常

如果只想修复**损坏的链接**、不碰正常链接，建议使用单文件模式逐个处理。

### Q: 同文件名怎么处理？

索引基于文件名（不区分大小写）。如果有多个同名文件在不同目录，索引中只保留最后一个。建议保持文件名唯一。

### Q: 外部链接（`https://...`）会被处理吗？

不会。两个脚本都会跳过 `http://`、`https://`、`data:`、`file://` 开头的链接。

### Q: 支持的图片格式有哪些？

`.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp` `.svg`（以及 `final_fix.py` 额外支持 `.ico` `.tiff` `.tif`）
